# Mimir pipeline

The diagram is drawn in SVG by `scripts/mimir-pipeline.mjs`, following the site-art palette and print contours. It uses a person shown from the waist up with their hands resting together for the user, a matte phone for Mimir, a sorting cabinet for Hermes, a literal mail bridge, an indexing tray, and a tear-off calendar for synchronization. Pi is a rounded mechanical robot with a domed olive helmet, circular cream lenses, a compact carbon torso, and slender articulated limbs. The supplied Pi logo stays unchanged on its chest. The latest user reference informed the rounded silhouette, while the SVG uses original print contours, shallow planes, and simplified mechanical details. The model is a layered printed tile, SQLite retains a recognizable cylinder, and calendar mirrors are stacked calendar sheets. The harness has one caption and no separate agent badge or label. Labels sit outside the objects. Curved threads connect the silhouettes, with shallow overlap and fine dry-ink marks.

Use `{% mimirPipeline "unique-figure-id" %}` in a Nunjucks-enabled post. The desktop drawing is animated. Mobile uses a separate static overview, with simple system cards, an email database cylinder, calendar files, and directional arrows. It retains Pi and the local model as distinct nodes, along with the email and calendar synchronization paths. Each composition has unique SVG definition IDs.

The desktop user is a waist-up editorial portrait with natural adult proportions, simplified facial planes, and relaxed hands. It uses the generated transparent `mimir-user-editorial.png`, encoded as a 512-pixel-wide WebP for the diagram. The initially generated detailed portrait was simplified at the user's request before integration. The selected generation/edit prompts are in `MIMIR-USER.md`. The desktop robot uses a domed helmet, narrow arm links, compact hands, and flat overlapping boots. Mobile uses a labeled Pi card without an illustration. Its compact cards have cut-paper contours, shallow offset print layers, and sparse cream dry-ink marks. Terracotta anchors Mimir, dark olive anchors Pi, and pale olive and warm ochre support Hermes and the model. The email cylinder has an olive lid and the calendar file has a terracotta folded edge. Text and arrow contrast remain clear at phone sizes.

Calendar requests and returned sources use separate connection points and lanes. The outgoing calendar curve advances continuously toward the files, with no sideways turn-back at its endpoint. The user and Mimir–Pi connections stop short of the silhouettes, leaving room for both arrowheads and the moving message. Desktop routes are uninterrupted curves, and moving objects follow the same paths as their arrows. The mobile overview uses simple static arrows.

The request sequence alternates email and calendar searches in a 28-second loop. Mail sync and calendar sync run on separate 11-second illustration cycles. The calendar transfer takes 5.5 seconds, about 20% less than before, with a different phase from mail sync. These timings explain the architecture, they do not represent actual synchronization schedules or request latency.

Each request retains one pigment through its entire round trip, including both model calls, tool calls, sources, and the final answer. Email requests use terracotta, calendar requests use warm ochre. The active connection shares the message color, while synchronization uses cream documents with olive outlines. Traces and messages share one step sequence and the same visibility timing. No legend or visible explanatory caption is needed, the figure is named by its heading and the SVG retains its accessible description.

Moving objects use Core Animation’s `easeInEaseOut` curve, `cubic-bezier(0.42, 0, 0.58, 1)`, to accelerate and settle on each connection. Short fades soften their appearance and disappearance. The SVG uses `calcMode="spline"` with a curve for every interval, including stationary portions of the cycle. Loop boundaries have unique key times. References: [Apple’s timing guide](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/Animation_Types_Timing/Articles/Timing.html) and [SVG keySplines](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/keySplines).

Mail sync extracts text and builds local embeddings for email search. Calendars are separate ICS mirrors, they do not enter the email vector index.

`assets/scripts/mimir-pipeline.js` starts only the desktop SVG animation, provides pause/play, honors reduced motion, and pauses when offscreen, hidden, or in the mobile layout. On mobile, the animation control is hidden and the SVG contains no animations. The desktop timeline resumes when returning to the wide layout. Without JavaScript both diagrams remain static. Styles are scoped to the component in `styles.css`.

The controller is fingerprinted and published by the asset pipeline. This note and the generating source stay out of the public output.
